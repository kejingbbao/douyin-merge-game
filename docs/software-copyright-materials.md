## 二、源代码抽取实操（方法清单，不真抽）

### 2.1 可作为源码来源的本仓库文件

| 文件                                                                            | 内容                              | 适用       |
| ----------------------------------------------------------------------------- | ------------------------------- | -------- |
| `game.js`                                                                     | 抖音小游戏入口：渲染 / 触摸输入 / 广告位 / 排行榜调用 | 程序主体（前段） |
| `src/logic.js`                                                                | 纯逻辑：合成 / 计分 / 判负                | 核心算法（前段） |
| `src/hmac.js`                                                                 | HMAC-SHA256 签名（防刷分）             | 安全模块     |
| `src/ladder.js` / `src/room.js`                                               | 天梯榜 / 实时房间对战逻辑                  | 联网玩法     |
| `server/index.js` / `server/store.js` / `server/room.js` / `server/ladder.js` | Vercel Serverless 后端、存储、对战、天梯   | 后端（后段）   |
| `server/worker.js` / `server/verify.js` / `server/vercel.json`                | Cloudflare Worker 入口、验签、部署配置    | 后端辅助     |

### 2.2 抽取步骤（照做）

1. **确定"前 30 页"与"后 30 页"**：指程序的**起始部分**与**结尾部分**各连续 30 页，中间可省略（用"……"或截断说明衔接，但首尾必须连续、不能跳行）。
2. **合并候选文件**：按"前端入口 → 核心逻辑 → 后端"顺序拼接，优先用 `game.js → src/*.js → server/*.js`。
3. **去空行凑行数**：每页正文 **≥50 行**（不含页眉页脚）；空行不计数，必要时合并连续逻辑段、保留注释以满足行数。
4. **加必要注释**：关键函数、模块用途加中文注释，证明可读性与独创性（"含必要注释"为硬性要求）。
5. **标注页码**：每页右上角表头含「软件名称 / 版本号 / 第 X 页 共 Y 页」。
6. **行数核验**：前后各 30 页 × 50 行 = 至少 3000 行（总计 ≥3000 行即达标，建议略超以留余量）。
7. **格式**：A4、宋体小四（或等宽字体）、单面打印提交；电子版 PDF 与 Word 各备一份。
8. **不提交整库**：仅提交鉴别材料（前后各 30 页），勿夹带 `test/`、`node_modules/`、配置文件等非核心代码。

## 三、软件说明书 / 用户手册撰写要点

要求：≥15 页，截图 + 文字，证明软件可运行、功能完整。建议章节：

1. **软件概况**：名称《合成能量》、版本 V1.0、用途（2048 式合成休闲小游戏）、著作权人（个人）。
2. **运行环境**：抖音小游戏 `tt.*` 运行时（抖音 App 内）、JavaScript、Canvas；后端 Vercel Serverless + Upstash Redis，域名 `kejingbbao.cn`（已加白名单 + EdgeOne HTTPS）。
3. **安装与进入**：抖音开发者工具导入 → 预览 / 抖音内打开（个人开发者提审发布）。
4. **功能与操作截图**（每功能配 1–2 张图 + 说明）：
   - 合成玩法（上下左右滑动合并、随机生成方块、判负）
   - 震动反馈开关
   - 结束排名与"再来一局"
   - 天梯榜（积分、名次）
   - 实时房间对战（匹配、对战、战绩）—— 呼应 `tt.login` 实名
   - 排行榜（全球榜、前 100 名、HMAC 防刷分）
5. **核心流程图**：可用 mermaid 或手绘导出，示例如下（玩法主循环）：
   ```mermaid
   flowchart TD
     A[开始/进入游戏] --> B[棋盘初始化]
     B --> C[滑动输入]
     C --> D{有相同相邻?}
     D -- 是 --> E[合并+计分+震动]
     D -- 否 --> C
     E --> F[随机生成新方块]
     F --> G{满盘且无可合并?}
     G -- 是 --> H[游戏结束→排名/再来一局]
     G -- 否 --> C
   ```
6. **数据安全说明**：HTTPS 传输、HMAC 签名防刷分、数据存 Upstash（呼应隐私政策）。
7. **版本与版权**：声明代码/美术/名称归属运营者，遵守平台规范。

> 团队可据上述要点起草初稿；**截图须为真实运行画面**，提审材料造假将驳回。
